# Vexil Document Specification

Vexil (.vxl) is a *high-density*, _context-preserving_ structured text format engineered for LLM context windows, deterministic parsing, and semantic chunking. It combines the readability of Markdown with strict single-pass stream guarantees.

---

@id: sec-syntax-overview
## Structural Overview

Vexil partitions documents into deterministic block nodes without lookahead buffers. Inline styling supports *bold text*, _italic emphasis_, `inline code`, ~strikethrough~, and [hyperlinks](https://vexil.org). Visual assets are referenced using media syntax: [System Architecture Diagram](img:architecture.png).

### List Structures

Document hierarchies utilize strict two-space indentation increments for nested structures.

- Unordered item at root level
  - Nested unordered child item
  - Another nested sibling item
- Secondary root item

Ordered workflows support explicit indices and automatic counters:

1. Initial installation step
  . Nested sub-procedure
  . Secondary validation sub-procedure
2. Final deployment phase

Actionable items are tracked via deterministic task list states:

[x] Implement single-pass block tokenizer
[x] Add symmetric inline delimiter stack
[ ] Benchmark zero-copy stream chunker

!warning: Deprecated Syntax

```

Tabular datasets define explicit column structures and support escaped pipes and inline code spans:

@id: tbl-syntax-matrix
@title: Vexil Node Syntax Matrix
::table [Construct | Syntax Pattern | Target Output]
- Heading Level 1 | `# Title` | `<h1>Title</h1>`
- Code Fence | `lang id` | `<pre><code class="language-lang">`
- Escaped Pipes | Cell \| Alpha | Table cell with literal pipe
- Inline Code Span | `a | b` | Code span with pipe
::
